A ticket-generating subroutine needs to remember the next number between calls. An ordinary lexical counter initialized inside the subroutine would restart each time, while a package variable would expose bookkeeping outside the routine. Use `state` to keep that counter local while retaining its updated value. This example assigns tickets to a fixed customer list and makes one-time initialization visible.

```perl
use v5.36;

sub initialize_counter {
    say 'Initializing ticket counter';
    return 1000;
}

sub issue_ticket ($customer) {
    state $next_id = initialize_counter();
    my $ticket_id = $next_id++;
    return sprintf '%s: T%04d', $customer, $ticket_id;
}

my @customers = ('Ada', 'Lin', 'Ada');
for my $customer (@customers) {
    say issue_ticket($customer);
}

```

Expected output:

```text
Initializing ticket counter
Ada: T1000
Lin: T1001
Ada: T1002

```

The `state` declaration creates a lexical variable whose value persists between calls to `issue_ticket`. Its initializer runs only once, when execution first reaches the declaration. The initialization message therefore appears before the first ticket, but not before subsequent tickets. The `state` feature was introduced in Perl 5.10; this program targets Perl 5.36, where `use v5.36` enables it along with `strict` and `warnings`.

Each call copies the current counter into the ordinary lexical variable `$ticket_id`, then increments the persistent counter using postfix `++`. The returned string formats that saved number with a T prefix and at least four digits. Unlike `$next_id`, `$ticket_id` is created afresh for each call.

All three calls reach the same `state` declaration, so they use one sequence. The repeated customer name does not create or select a separate counter: Ada receives T1000 and later T1002. This makes the function suitable for assigning consecutive identifiers within one running program, rather than maintaining per-customer totals.

The counter is private to its lexical scope, not a package global that unrelated code can directly name. However, persistence here means persistence during execution, not durable storage. Starting the program again initializes a new counter at 1000. Separate program runs can therefore produce identical identifiers. Use this pattern when process-local numbering is sufficient, not when identifiers must remain unique across restarts or independent processes.

Example tested with Perl 5.36.
