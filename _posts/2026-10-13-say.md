Small batch scripts often need a readable status report: a heading, one line per item, and a final count. Repeating an explicit newline on every output statement adds clutter and makes missing line endings easier to overlook. Use `say` when each call should finish a line. This example reports three jobs and calculates how many have completed, keeping the output statements close to the report's visible structure.

```perl
use v5.36;

my @jobs = (
    { name => 'Import customers', status => 'done' },
    { name => 'Rebuild index',    status => 'pending' },
    { name => 'Export invoices',  status => 'done' },
);

my $completed = 0;

say 'Batch status';
say '------------';

for my $job (@jobs) {
    say $job->{name}, ': ', $job->{status};
    ++$completed if $job->{status} eq 'done';
}

say '';
say 'Completed: ', $completed, '/', scalar @jobs;

```

Expected output:

```text
Batch status
------------
Import customers: done
Rebuild index: pending
Export invoices: done

Completed: 2/3

```

The `say` feature was introduced in Perl 5.10. This program targets Perl 5.36: `use v5.36` enables `say`, along with `strict` and `warnings`, so no separate feature declaration is needed.

Each call prints its arguments and appends a newline. Inside the loop, the job name, the literal colon and space, and the status are separate arguments. They form one output line, not three lines. The newline comes after the complete argument list.

The punctuation is explicit because `say` does not automatically insert spaces between arguments under the program's default settings. This lets the report combine labels and values without first building a temporary string. The final call combines a label, the computed completion count, a slash, and the total number of jobs. The array preserves the report's input order.

The call with an explicit empty string produces the blank line separating details from the summary. Unlike a bare `say` statement, it does not read `$_`, so it works independently of that variable's value and avoids an uninitialized-value warning when `$_` is undefined.

Reserve `say` for output that should end a line. It appends its newline even when an argument already ends with one, so passing newline-terminated text can produce an extra blank line. For partial lines or precisely controlled line endings, use `print` instead.

Example tested with Perl 5.36.
